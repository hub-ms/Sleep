     소음측정 원리/정확도 개선 + 수면단계 분류 모델(F1≥0.75) 개선 로드맵

     Context

     두 가지 질문에 답하기 위한 산출물입니다.
     1. 현재 앱에서 수면측정 시작 시 소음측정이 어떤 원리로 동작하는지, 정확도를
        어떻게 높일 수 있는지
     2. ml/ 폴더의 수면단계 분류 모델을 F1 score 0.75 이상으로 끌어올리기 위해
        어떤 기법을 적용해야 하는지 (pdf/ 폴더의 관련 논문 5편 근거 포함)

     코드 탐색 결과 ML 파이프라인은 현재 end-to-end로 실행 불가능한 상태(정규화
     통계 파일 없음, PSG 데이터 미전처리, 테스트셋 코드상 계산되지만 미사용,
     평가/메트릭 코드 자체가 없음)임이 확인되었습니다. 기존에 저장된 "버그
     수정을 신규 기능보다 우선한다"는 원칙과도 일치하게, 이 로드맵은 먼저 
     파이프라인을 정상 동작 + 측정 가능한 상태로 복구(Phase 0)한 뒤, 논문 기반 
     F1 향상 기법을 단계적으로 적용하는 순서로 구성했습니다.

     이 작업은 설명 + 개선 로드맵 문서 산출만 목표로 하며, 코드는 수정하지
     않습니다. (사용자 확인됨)

     원시 캡처 (SensorBridge.kt)
     - AudioRecord(우선 AudioSource.UNPROCESSED, 미지원 시 AudioSource.MIC로
       폴백) 기반, mono 16bit PCM
     - 샘플레이트는 기기별 native rate를 조회해 동적으로 선택([native, 44100, 
       48000, 16000] 순 시도)
     - FFT_SIZE=1024, HOP_SIZE=512(50% overlap), Hann window 적용
     - 자체 구현 radix-2 FFT → 주파수 빈별 A-weighting(IEC 61672 근사) + 일반
       마이크 주파수보정 커브 적용 → 에너지 합산
     - BASE_SPL_OFFSET_DB = 94.0(고정 SPL 보정 상수)로 디지털 에너지를 절대 dB로
       환산, NOISE_FLOOR_DB=30/최대 120dB로 클램프
     - attack(~35ms)/release(~1.5s) 비대칭 지수평활(사운드레벨미터의 "Fast"
       응답과 유사)

     집계/저장
     - 1초 단위로 60개 순환버퍼 통계를 내고, 30초 버킷(WINDOW_BUCKET_MS)으로
       EnvironmentFeature(avg/min/max/stddev) 생성
     - 세션 종료 시 SleepSession.Environment.stats/flags는 전체 야간 평균이 
       아니라 마지막 30초 버킷 값만 사용(environmentFeatures.lastOrNull()) —
       리포트에 표시되는 "평균 소음" 배지가 실제로는 전체 밤이 아닌 마지막
       구간만 반영
     - isNoiseDanger는 NOISE_DANGER_THRESHOLD=60dB 고정 임계값
     - "소음 상승으로 인한 각성" 추정 로직은 peakNoise ≥ avgNoise × 1.5 휴리스틱

     Part 2. 수면단계 분류 모델 개선 로드맵 (F1 ≥ 0.75)

     2-1. 현재 구조 요약

     - 아키텍처: Dual-domain(PSG / Accel) CNN+Transformer 하이브리드.
       Epoch(30초, 1500×8) → 멀티스케일 Conv1D → Transformer 인코더(PSG는
       2-layer+attention, Accel은 plain CNN) → 60-epoch 컨텍스트를 공유 4-layer
       Transformer(FiLM 도메인 컨디셔닝)로 처리 → 도메인별
       4클래스(Wake/Light/Deep/REM) 분류
     - 입력: PSG(EEG/EOG/EMG, Sleep-EDF) 8채널,
       Accel(가속도/기울기/심박/HRV/MFCC 등, BIDSleep+Sleep-Accel) 8채널 — 단,
       mfcc_energy는 하드코딩 0으로 실제로는 미구현
     - 전처리: per-channel z-score 정규화 스크립트(compute_stats.py)는 존재하나
       PSG/Accel 도메인 정규화 파일이 현재 없음 → 학습 자체가 불가능한 상태
     - 학습: focal loss + label smoothing + 클래스 가중치, subject-level
       70/15/15 분할(정렬 순서 기반, 셔플 없음)
     - 평가: classification_report import만 있고 호출 코드 없음 — 테스트셋이
       계산은 되지만 어디서도 쓰이지 않음, 저장된 메트릭/컨퓨전매트릭스 파일
       전무
     - 후처리: Viterbi/최빈값 스무딩(postprocess.py)이 구현은 되어 있으나
       학습/추론 파이프라인 어디에도 연결되지 않은 고아 코드

     2-2. Phase 0 — 파이프라인 정상화 (반드시 선행, 사용자 확인됨)

     F1 수치를 논하기 전에 측정 가능한 baseline이 있어야 함. 다음이 없으면 이후

     1. build_dataset_hybrid.py를 sleep_edf 원본(ml/data/sleep_edf/subjects/의

     3. train.py에 테스트셋 평가 코드 추가: 이미 계산되는 edf_te/bid_te/acc_te를

        파이프라인에 맞게 갱신
     7. Phase 0 완료 후 첫 baseline F1(macro/클래스별)을 측정하고 기록 — 이후
        모든 개선의 비교 기준점

     2-3. Phase 1 — 시간적 맥락(전이/변동성) 특징 강화 (최우선, 논문3·4 근거)

     - 현재 각 30초 epoch은 그 자체의 특징만 사용. 논문3(HRV 연구, 전환 전후
       변동성 특징 추가로 정확도 +9.2%p)과 논문4(Bi-LSTM에 과거 K-epoch 투입,
       balanced accuracy +5.7%p)가 공통적으로 시간적 맥락이 단일 epoch보다
       예측력이 크다는 것을 실증
